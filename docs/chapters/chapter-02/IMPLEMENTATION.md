# Chapter 2: Implementation

## Plan

1. Create `packages/db` with Drizzle ORM, drizzle-kit and a `createDatabase()`
   client.
2. Turn every entity in the scope doc into a Drizzle table, grouped by domain,
   with enums, foreign keys, indexes and one check constraint.
3. Enable pgvector in a hand-written first migration; generate the schema
   migration with drizzle-kit.
4. Move Better Auth onto the Drizzle adapter and delete Chapter 1's
   migration script.
5. Introduce the Repository pattern with two small repositories.
6. Add a seed script (templates + demo account).
7. Run migrations once before all tests; add database tests.

## Acceptance criteria

- [x] `pnpm setup` starts Postgres, migrates and seeds a fresh machine.
- [x] All 20 entities from the scope doc exist as tables (24 tables in total).
- [x] `pnpm db:generate`, `pnpm db:migrate` and `pnpm db:studio` work from the root.
- [x] Sign-up, sign-in and sign-out still work on the web (now through Drizzle).
- [x] The seeded demo account can sign in; running the seed twice creates no duplicates.
- [x] The demo account is never created when `NODE_ENV=production`.
- [x] The database rejects a thread with neither an agent nor a room.
- [x] Deleting a user deletes everything they own.
- [x] Vector search returns the most similar memory.
- [x] A fresh database (as in CI) migrates once and all tests pass.
- [x] Lint, type-check, tests and the web build pass.

### `apps/api` changes

- `src/db.ts` exports `db = createDatabase(env.DATABASE_URL)` (was a raw pool).
- `src/auth.ts` uses `drizzleAdapter(db, {provider: 'pg', usePlural: true, schema})`.
- `scripts/migrate.ts` deleted; `scripts/seed.ts` added.
- Tests clean up with Drizzle instead of raw SQL.

### Root changes

- `pnpm setup` = `docker compose up -d && pnpm db:migrate && pnpm db:seed`.
- New scripts: `db:migrate`, `db:generate`, `db:studio`, `db:seed`.
- `turbo.json`: `test` depends on `@binary/db#db:migrate`.
- `.prettierignore`: generated migrations are left untouched.

## Decisions

| Decision                                                     | Why                                                                                                             |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Drizzle ORM                                                  | SQL-like and readable, schema in TypeScript, first-class pgvector, Better Auth adapter.                         |
| One schema file per domain                                   | Each file is short enough to read in one go and maps to a later chapter.                                        |
| Plural table names, `snake_case` columns                     | Postgres convention; `casing: 'snake_case'` keeps TypeScript in camelCase. `usePlural: true` tells Better Auth. |
| UUIDs for our tables, text ids for auth tables               | Better Auth generates its own string ids; our tables use `gen_random_uuid()`.                                   |
| All tables now, no relations helpers                         | The data model is the LLD lesson. Drizzle `relations()` are added when a chapter first needs nested queries.    |
| Repositories live in `packages/db`                           | The API today and the Trigger.dev jobs later both need them.                                                    |
| Repositories as small classes with the db in the constructor | Shows the Repository pattern and constructor injection; easy to fake in tests.                                  |
| Migrate once before tests (turbo dependency)                 | Prevents test packages racing to create tables on a fresh CI database.                                          |
| Embedding size 1536                                          | Matches OpenAI `text-embedding-3-small`; Chapter 12 revisits it.                                                |
| `numeric` for cost                                           | Exact decimals; floats drift when summed.                                                                       |
