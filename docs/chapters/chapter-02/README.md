# Chapter 2: Database and ORM layer setup

**Goal:** one typed, versioned database layer for the whole project. Every
table Binary will ever need exists after this chapter, and every app talks to
Postgres through the same Drizzle client.

## What you get

- A new `packages/db` package with [Drizzle ORM](https://orm.drizzle.team)
- The full schema: **20 entities** from the scope doc, plus Better Auth's
  session/account/verification tables and two join tables (24 tables, 16 enums)
- pgvector enabled, with a 1536-dimension `memories.embedding` column and an
  HNSW index for similarity search
- SQL migrations generated by drizzle-kit and applied with `pnpm db:migrate`
- Better Auth moved from its own SQL onto the Drizzle adapter
- The Repository pattern: `UserRepository` and `AgentTemplateRepository`
- A seed script: 4 agent templates and a demo account
- 11 new tests against a real database, including vector search

## Run it

```bash
pnpm install
pnpm setup      # Postgres + migrations + seed
pnpm dev        # sign in as demo@binary.dev / binary-demo-password
pnpm db:studio  # browse the tables in Drizzle Studio
```

### Coming from Chapter 1?

Chapter 1 let Better Auth create singular tables (`user`, `session`, …).
Chapter 2 uses plural, Drizzle-managed tables (`users`, `sessions`, …), so
**accounts created in Chapter 1 are not carried over.** Run `pnpm setup` and
sign up again (or use the demo account). To remove the old tables:

```sql
DROP TABLE IF EXISTS "session", "account", "verification", "user" CASCADE;
```

Or start completely fresh with `docker compose down -v && pnpm setup`.
